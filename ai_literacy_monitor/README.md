# AI Literacy Monitor

A lightweight daily digest tool for the **SUNY Poly AI Exploration Center**.
It polls RSS feeds covering AI literacy research and higher-education news, deduplicates
against previous runs, and asks Claude to produce a concise bullet-point report.
The report is saved as a dated Markdown file and emailed to the configured recipient.

---

## What it monitors

| Source | Coverage |
|--------|----------|
| Google Alerts RSS (×3) | "AI literacy" pedagogy · "AI literacy" higher education · generative AI teaching ethics |
| Inside Higher Ed | Higher-ed news |
| Chronicle of Higher Education | Higher-ed news |
| EdSurge | Ed-tech news |
| EDUCAUSE | IT/ed-tech in higher education |

## Quick start

### 1 — Clone & install

```bash
cd ai_literacy_monitor
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

### 2 — Set up Google Alerts RSS feeds

Google Scholar does not expose a public RSS API, so use **Google Alerts** as a proxy:

1. Go to <https://www.google.com/alerts>
2. Create three alerts (set delivery to *RSS feed*):
   - `"AI literacy" pedagogy`
   - `"AI literacy" higher education`
   - `generative AI teaching ethics`
3. Copy each RSS URL (shown after you create the alert) into `config.yaml` under the
   `feeds:` section, replacing the `REPLACE_WITH_…` placeholders.

### 3 — Configure

Edit `config.yaml`:

- **`output.directory`** — point to your SharePoint folder (mounted as a network drive
  or via OneDrive sync). Example on macOS: `/Users/steve/Library/CloudStorage/OneDrive-SUNYPolytechnic/AILiteracy/reports`
- **`email`** — confirm SMTP host/port for your institution.

### 4 — Add secrets

```bash
cp .env.example .env
# Edit .env and fill in ANTHROPIC_API_KEY and SMTP_PASSWORD
```

Get your API key from <https://console.anthropic.com>.

### 5 — Test with a dry run

```bash
python monitor.py --dry-run --show-new
```

This fetches feeds and prints what it found, but skips Claude and email.

### 6 — Run for real

```bash
python monitor.py
```

## Scheduling (run daily automatically)

### macOS / Linux — cron

```cron
# Run at 7:00 AM every day
0 7 * * * /path/to/.venv/bin/python /path/to/ai_literacy_monitor/monitor.py >> /tmp/ai_literacy_monitor.log 2>&1
```

### macOS — launchd (recommended over cron)

Create `~/Library/LaunchAgents/edu.sunypoly.ailiteracymonitor.plist` — see Apple's
[launchd documentation](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/ScheduledJobs.html).

### Windows — Task Scheduler

Use Task Scheduler to run `python monitor.py` daily; point the working directory at
the `ai_literacy_monitor/` folder so the `.env` file is found automatically.

## Report format

Reports are saved as `ai_literacy_YYYY-MM-DD.md`:

```markdown
# AI Literacy Digest — 2026-02-19

> Generated by AIXworkbench AI Literacy Monitor · 2026-02-19 14:05 UTC

• Universities piloting AI literacy frameworks that centre ethical reasoning
  alongside tool proficiency have seen higher student engagement scores. (Inside Higher Ed)
• A preprint argues that current AI literacy curricula underweight data-governance
  and power-asymmetry dimensions. (Google Alerts — AI literacy pedagogy)
...

---
*12 new item(s) processed from 7 source(s).*
```

## Deduplication

A JSON state file (`state/seen_items.json`) records SHA-256 hashes of every item URL
processed. Items already in the state file are skipped. Entries older than 30 days
are pruned automatically to keep the file small.

---

## Keyword pre-filter

Before calling Claude, items are checked against the `filter_keywords` list in
`config.yaml`. Items whose title and summary contain none of the keywords are dropped.
Adjust the list to broaden or narrow coverage.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| `ANTHROPIC_API_KEY is not set` | Missing `.env` | Copy `.env.example` → `.env` and add your key |
| `Feed parse issue` warning | Feed URL is wrong or unavailable | Verify the URL in a browser; check Google Alerts setup |
| Report written to fallback dir | SharePoint path unreachable | Mount the drive / check `output.directory` in config |
| Email not sent | `SMTP_PASSWORD` missing or wrong host | Check `.env` and `email` section in config |
| Empty digest every day | All items filtered by keywords | Run with `--show-new` to inspect; widen `filter_keywords` |
